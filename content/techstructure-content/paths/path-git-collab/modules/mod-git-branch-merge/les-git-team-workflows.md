# Branching Strategies and Protected Branches

**Lesson ID:** `les-git-team-workflows`  
**Classification:** Core  
**Module:** Merging & Advanced History

## Learning goal

Compare Trunk-Based Development and feature branching.

## Core concept

A team workflow defines branch naming, review expectations, CI requirements, release practices, and how changes are integrated. Keep branches focused, sync regularly, communicate breaking changes, and protect the default branch. The best workflow is the simplest one that supports the team’s release risk and collaboration needs.

## Worked example / guided practice

Write a short workflow for a student team: feature branch, small commits, PR review, required tests, and merge policy. Include what to do when a branch becomes outdated.

## Common mistake to avoid

Workflow consistency matters more than adopting a fashionable branching model.
