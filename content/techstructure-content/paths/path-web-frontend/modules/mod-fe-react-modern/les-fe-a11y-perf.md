# Web Accessibility (a11y) and Frontend Performance

**Lesson ID:** `les-fe-a11y-perf`  
**Classification:** Core  
**Module:** Component Architecture (React)

## Learning goal

Audit keyboard navigation, ARIA semantics, and bundle bloat.

## Core concept

Accessibility means people can perceive, navigate, and operate the interface, including with keyboards and assistive technology. Use semantic HTML, visible focus, labels, sufficient contrast, meaningful alt text, and sensible focus management. Performance work should be measured and prioritize user-visible bottlenecks such as oversized assets, unnecessary renders, and slow data loading.

## Worked example / guided practice

Keyboard-test a form and modal: move focus, activate controls, close the modal, and verify focus returns sensibly. Measure a slow page before selecting one optimization.

## Common mistake to avoid

Accessibility and performance are design requirements, not optional polish at the end.
