# What a Software System Is

**Lesson ID:** `les-arch-what-is-system`  
**Classification:** Core  
**Module:** Software Systems & Request Lifecycles

## Learning goal

Deconstruct a product into UI, business logic, data, and integrations.

## Core concept

A software system is a set of components that interact to provide capabilities within constraints. Components can include a user interface, services, databases, queues, external providers, and operational tooling. Architecture describes important structures and decisions, including responsibilities, interfaces, data flow, and quality attributes such as reliability, security, and maintainability.

## Worked example / guided practice

For a simple learning app, list the user-facing capabilities, major components, and two quality attributes. Explain which decisions belong to architecture versus a local implementation detail.

## Common mistake to avoid

Architecture is not just a diagram or a list of frameworks; it is about boundaries, responsibilities, and trade-offs.

## Practice

2. Apply it to a small example in your current project or a disposable practice project. Record the command, code, or diagram you used and the observed result.
3. Describe one failure mode and how you would diagnose it without making broad, destructive changes.

## Mastery task

Produce a small artifact demonstrating the learning goal: a working code example, terminal transcript, architecture sketch, or written decision as appropriate. Include the expected behavior, actual observation, and one limitation.

## Completion criteria

- Explain the core concept without relying on a memorized definition alone.
- Complete the practice and explain why the result follows.
- Identify the relevant limitation or safety consideration.
